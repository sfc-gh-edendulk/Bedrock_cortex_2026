⏱️ Module Overview

Estimated time: 15 minutes

In this module, you'll create a Semantic View that enables Cortex Analyst to understand your data in business terms.

💡 What is a Semantic View? A Semantic View is like a dictionary for your data. It tells AI what "revenue," "profit," and "region" mean in your context, enabling accurate natural language to SQL translation.

Understanding the Data

First, let's understand the revenue data we loaded earlier:

Table Description Key Columns
DAILY_REVENUE Overall daily revenue metrics DATE, REVENUE, COGS, FORECASTED_REVENUE
DAILY_REVENUE_BY_PRODUCT Revenue broken down by product line DATE, PRODUCT_LINE, REVENUE, COGS
DAILY_REVENUE_BY_REGION Revenue broken down by sales region DATE, SALES_REGION, REVENUE, COGS 
-- Preview the data
SELECT * FROM WORKSHOP_DB.REVENUE_TIMESERIES.DAILY_REVENUE LIMIT 5;
SELECT DISTINCT PRODUCT_LINE FROM WORKSHOP_DB.REVENUE_TIMESERIES.DAILY_REVENUE_BY_PRODUCT;
SELECT DISTINCT SALES_REGION FROM WORKSHOP_DB.REVENUE_TIMESERIES.DAILY_REVENUE_BY_REGION;

Step 1: Create the Semantic View

The Semantic View defines your data model in YAML format, describing tables, dimensions, measures, and relationships.

USE DATABASE WORKSHOP_DB;
USE SCHEMA REVENUE_TIMESERIES;
USE WAREHOUSE WORKSHOP_WH;

-- Create semantic view from YAML using stored procedure
CALL SYSTEM$CREATE_SEMANTIC_VIEW_FROM_YAML(
  'WORKSHOP_DB.REVENUE_TIMESERIES',
$$
name: REVENUE_SEMANTIC_VIEW
description: >
  Semantic model for analyzing company revenue data across time, 
  products, and regions. Use this to answer questions about revenue 
  trends, profitability, and forecasts.

tables:
  - name: daily_revenue
    description: Daily aggregate revenue metrics for the entire company
    base_table:
      database: WORKSHOP_DB
      schema: REVENUE_TIMESERIES
      table: DAILY_REVENUE
    dimensions:
      - name: date
        description: The calendar date of the revenue record
        expr: DATE
        data_type: DATE
    measures:
      - name: revenue
        description: Total revenue in USD for the day
        expr: REVENUE
        data_type: FLOAT
        default_aggregation: SUM
      - name: cogs
        description: Cost of goods sold in USD
        expr: COGS
        data_type: FLOAT
        default_aggregation: SUM
      - name: profit
        description: Gross profit (Revenue minus COGS)
        expr: REVENUE - COGS
        data_type: FLOAT
        default_aggregation: SUM
      - name: profit_margin
        description: Profit margin as a percentage
        expr: (REVENUE - COGS) / NULLIF(REVENUE, 0) * 100
        data_type: FLOAT
        default_aggregation: AVG
      - name: forecasted_revenue
        description: Predicted revenue from forecasting model
        expr: FORECASTED_REVENUE
        data_type: FLOAT
        default_aggregation: SUM

  - name: daily_revenue_by_product
    description: Daily revenue broken down by product line
    base_table:
      database: WORKSHOP_DB
      schema: REVENUE_TIMESERIES
      table: DAILY_REVENUE_BY_PRODUCT
    dimensions:
      - name: date
        description: The calendar date
        expr: DATE
        data_type: DATE
      - name: product_line
        description: The product category or line of business
        expr: PRODUCT_LINE
        data_type: VARCHAR
        sample_values:
          - "Electronics"
          - "Clothing"
          - "Home & Garden"
    measures:
      - name: revenue
        description: Revenue for the product line
        expr: REVENUE
        data_type: FLOAT
        default_aggregation: SUM
      - name: profit
        description: Profit for the product line
        expr: REVENUE - COGS
        data_type: FLOAT
        default_aggregation: SUM

  - name: daily_revenue_by_region
    description: Daily revenue broken down by sales region
    base_table:
      database: WORKSHOP_DB
      schema: REVENUE_TIMESERIES
      table: DAILY_REVENUE_BY_REGION
    dimensions:
      - name: date
        description: The calendar date
        expr: DATE
        data_type: DATE
      - name: sales_region
        description: Geographic sales region
        expr: SALES_REGION
        data_type: VARCHAR
        sample_values:
          - "North America"
          - "Europe"
          - "Asia Pacific"
    measures:
      - name: revenue
        description: Revenue for the region
        expr: REVENUE
        data_type: FLOAT
        default_aggregation: SUM
      - name: profit
        description: Profit for the region
        expr: REVENUE - COGS
        data_type: FLOAT
        default_aggregation: SUM

verified_queries:
  - name: total_revenue_last_month
    question: What was the total revenue last month?
    sql: |
      SELECT SUM(revenue) as total_revenue
      FROM WORKSHOP_DB.REVENUE_TIMESERIES.DAILY_REVENUE
      WHERE DATE >= DATEADD(month, -1, CURRENT_DATE())
      
  - name: revenue_by_region
    question: Show revenue breakdown by region
    sql: |
      SELECT sales_region, SUM(revenue) as total_revenue
      FROM WORKSHOP_DB.REVENUE_TIMESERIES.DAILY_REVENUE_BY_REGION
      GROUP BY sales_region
      ORDER BY total_revenue DESC
$$
);

Step 2: Understanding the Semantic View Structure

Key Components

Component Purpose Example
name/description Human-readable context for the AI "Revenue Analytics"
tables Map to physical database tables DAILY_REVENUE
dimensions Columns you group/filter by product_line, sales_region
time_dimensions Date/time columns for trends date
measures Numeric values to aggregate revenue, profit
verified_queries Pre-validated question/SQL pairs Helps AI learn your patterns
💡 Why Descriptions Matter: The more descriptive your definitions, the better Cortex Analyst understands your data. "Revenue in USD for the day" is better than just "Revenue."

Step 3: Verify the Semantic View

-- Check that the semantic view was created
SHOW SEMANTIC VIEWS IN SCHEMA WORKSHOP_DB.REVENUE_TIMESERIES;

-- Describe the semantic view
DESCRIBE SEMANTIC VIEW REVENUE_SEMANTIC_VIEW;

-- Grant access (if needed for other roles)
GRANT SELECT ON SEMANTIC VIEW REVENUE_SEMANTIC_VIEW TO ROLE ACCOUNTADMIN;

Step 4: Test Cortex Analyst

While the full Cortex Analyst experience is through the REST API (which we'll use in the Agent module), we can verify our data is ready with some sample queries:

-- These are the kinds of questions Cortex Analyst will answer:

-- "What was total revenue last month?"
SELECT SUM(REVENUE) AS TOTAL_REVENUE
FROM DAILY_REVENUE
WHERE DATE >= DATEADD(month, -1, CURRENT_DATE());

-- "Show profit by region"
SELECT 
    SALES_REGION,
    SUM(REVENUE) AS REVENUE,
    SUM(REVENUE - COGS) AS PROFIT
FROM DAILY_REVENUE_BY_REGION
GROUP BY SALES_REGION
ORDER BY PROFIT DESC;

-- "What are the top products by revenue?"
SELECT 
    PRODUCT_LINE,
    SUM(REVENUE) AS TOTAL_REVENUE
FROM DAILY_REVENUE_BY_PRODUCT
GROUP BY PRODUCT_LINE
ORDER BY TOTAL_REVENUE DESC
LIMIT 10;
✅ How It Works: When you ask Cortex Analyst "What was profit by region?", it reads the Semantic View, understands that "profit" = REVENUE - COGS and "region" = SALES_REGION, then generates and runs the appropriate SQL.

🎉 Module Complete!

You've successfully created a Semantic View with:

  • ✅ Three tables mapped (daily_revenue, by_product, by_region)
  • ✅ Dimensions defined (date, product_line, sales_region)
  • ✅ Measures with aggregations (revenue, profit, profit_margin)
  • ✅ Verified queries for common questions
